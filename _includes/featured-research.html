{%- comment -%} Featured Research. Data: _data/featured_publications.yml, GENERATED by scripts/build_site_data.py from data/featured_publications.yml and already sorted by `order`. Each item gets its OWN bibliography tag so that (a) the site's normal jekyll-scholar path renders it -- custom.csl, the author bolding / et al. collapse / DOI hoisting in _plugins/jekyll_scholar.rb, and the button row in _layouts/bibtemplate.html all apply unchanged -- and (b) the summary can be interleaved. A single "key=A || key=B" query would work but cannot control ordering (BibTeX::Bibliography#query uses select, so results come back in file order regardless of the query's order). This relies on jekyll-scholar interpolating double-brace placeholders inside tag arguments: Jekyll::Scholar::Utilities#query calls #interpolate on every render. That is an internal detail of 7.1.3 (pinned in the Gemfile). If a future upgrade breaks it, the fallback is to have build_site_data.py generate this file with the bibkeys substituted literally -- same output, no interpolation. The cite and reference tags are NOT substitutes: they bypass bibtemplate.html, so the DOI and press-release buttons would disappear. NOTE: Liquid parses the body of a comment block even though it discards the output, so under error_mode: strict this prose must contain no Liquid syntax. The three --file arguments are static, so bibtex_paths does not change between iterations and the bibliographies are parsed once for the whole loop.
