{%- comment -%} Generic bilingual CV/bio section renderer. Data comes from _data/cv/*.yml, which is GENERATED by scripts/build_site_data.py -- see data/README.md. Dates arrive pre-rendered for both languages as row.date.en / row.date.ja, so there is no month-name or "ongoing dash" logic here on purpose. Params: rows (array, required) e.g. site.data.cv.appointments lang (string) "en" (default) | "ja" fields (string) comma-separated field names to concatenate sep (string) separator between fields; defaults to ", " class (string) extra class on the
    nofallback (string) comma-separated fields that must NOT borrow the other language when blank. A Japanese CV names the school rather than a bachelor's degree, so an empty degree_ja is deliberate and must not be filled in with "M.D.". A field that is missing on a given row is skipped, which is what lets one include serve merged datasets (an appointment has `position` and no `degree`; an education row is the other way round). Everything is emitted on a single line so kramdown treats the block as raw HTML instead of trying to parse the interior as Markdown. {%- endcomment -%} {%- assign lang = include.lang | default: "en" -%} {%- assign fields = include.fields | split: "," -%} {%- assign sep = include.sep | default: ", " -%} {%- assign nofb = include.nofallback | default: "" | split: "," -%}
      {%- for row in include.rows -%} {%- assign parts = "" -%} {%- for f in fields -%} {%- assign obj = row[f] -%} {%- assign v = obj[lang] -%} {%- unless nofb contains f -%}{%- assign v = v | default: obj.en -%}{%- endunless -%} {%- if v and v != "" -%} {%- assign v = v | escape_once -%} {%- if parts == "" -%}{%- assign parts = v -%} {%- else -%}{%- assign parts = parts | append: sep | append: v -%}{%- endif -%} {%- endif -%} {%- endfor -%} {%- assign d = row.date[lang] | default: row.date.en -%}
